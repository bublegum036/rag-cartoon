# Прогоны и смысловая приёмка

`evaluate run` выполняет вопросы; `evaluate score` отдельно проверяет решения
по смысловой приёмке. Планировщик и генератор получают только вопрос и свои
источники, без rubric, ожидаемого статуса и эталонных фильтров.

## Запуск

Сначала подготовьте `.venv`, `.env`, Qdrant и индекс по README. Для нового
прогона используйте новый каталог: существующий каталог не перезаписывается.

```bash
PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli evaluate run --label A --output artifacts/replay-A --prompt-version grounded-ru-v1 --k 3 --retrieval-k 10 --context-movies 3 --delay-seconds 10
PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli evaluate run --label B --output artifacts/replay-B --prompt-version grounded-ru-v2 --k 3 --retrieval-k 10 --context-movies 3 --delay-seconds 10
```

Это команды повторения эксперимента; сохранённые исходные прогоны находятся
в `artifacts/ab-A-2026-10-25` и `artifacts/ab-B-2026-10-25`. Во время исходного
A prompt v1 был значением по умолчанию; теперь по умолчанию используется v2.
Модель остаётся `gemini-3.1-flash-lite`. Бесплатность определяется Free Tier
проекта Google; приложение не включает billing и не меняет модель при ошибке.
Интервал 10 секунд ограничивает частоту, но не гарантирует доступность квоты.

`run` сначала фиксирует состав случаев, затем создаёт один RAG-сервис с
закреплённой коллекцией. Для каждого случая сохраняются:

- `case.json`: разметка для оценщика;
- `trace.json`: вопрос, план, hits, контекст, вычисление и ответ;
- `retrieved.json` и `retrieved-ids.json`: отдельные части и их ID/родительские источники;
- `context.json` и `answer.json`: контекст и финальный ответ отдельно;
- `error.json`: техническая ошибка или причина, почему случай не выполнялся.

`manifest.json` фиксирует параметры, модель, версии prompt/планировщика,
физическую коллекцию, идентификатор embeddings, fingerprint каталога, хеш
набора случаев и кода. Настройки и адаптеры целиком не сериализуются: ключи
не попадают в manifest. `results.json` содержит все случаи и состояния.

При программной подмене генератора `build_rag_runtime` и `build_rag` требуют
`generator_identity=GeneratorIdentity(model, prompt_version, max_output_tokens)`.
Эти значения задаёт владелец генератора: фабрика не может проверить настройки
произвольной реализации. Передавайте только безопасные идентификаторы без ключей.
Для подменённого генератора отдельный аргумент `prompt_version` запрещён;
настройте сам объект и укажите его фактические параметры в identity.
Штатный генератор получает метаданные из той же конфигурации, что используется
при его создании. Отсутствующая, лишняя или противоречивая identity отклоняется
до обращения к поисковому провайдеру.

Ошибки сервиса записываются отдельно, а не превращаются в `insufficient`.
При Gemini 401/403/429 дальнейшие запросы останавливаются; оставшиеся случаи
помечаются `not_executed`. Сбой создания сервиса фиксируется в manifest,
случаи остаются в учёте. CLI возвращает ненулевой код при таких ошибках.

## Смысловая приёмка

После `run` Recall и фильтры уже рассчитаны. `answer_acceptance_rate` остаётся
`null`, пока есть ответы без смыслового решения. Непроверенный ответ не считается
автоматически принятым или отклонённым.

Оценщик читает вопрос, rubric, ответ, ограничения и подтверждающие карточки.
Для открытых рекомендаций допустим другой фильм, если его сюжет и ограничения
подтверждаются. Совпадение названия или одной строки не является приёмкой.
Решения сохраняются в JSON следующего вида:

```json
{
  "reviewer": "Имя оценщика и способ проверки",
  "decisions": [
    {
      "case_id": "sea-short",
      "case_sha256": "хеш из results.json",
      "trace_sha256": "хеш из results.json",
      "rubric_passed": true,
      "facts_supported": true,
      "constraints_passed": true,
      "references_supported": true,
      "explanation": "Какие утверждения и источники проверены; почему rubric выполнен или нарушен."
    }
  ]
}
```

Замените подписи хешей реальными 64-символьными SHA-256 из ledger, а флаги
и объяснение заполните после проверки. JSON выше — описание формата, не готовая
разметка. `facts_supported` проверяет утверждения по карточкам, а
`references_supported` — действительно ли указанные ссылки поддерживают ответ.
Хеш случая включает rubric и ожидаемые условия; хеш trace связывает решение
с конкретным выводом. Решение от другого ответа или разметки отклоняется.

Офлайн-пересчёт сохранённых результатов:

```bash
PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli evaluate score --run-dir artifacts/ab-A-2026-10-25 --reviews artifacts/ab-A-2026-10-25/reviews.json
PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli evaluate score --run-dir artifacts/ab-B-2026-10-25 --reviews artifacts/ab-B-2026-10-25/reviews.json
```

Эти команды не вызывают Gemini, не читают `.env` и не требуют Qdrant.
`score` проверяет хеши, согласованность отдельных файлов с trace и структуру
источников. По каждому случаю записывает `judgment.json`, а в manifest —
провенанс скоринга. При повторном скоринге с неполной разметкой старое решение
не остаётся принятым: оно заменяется на `pending_review`.

Сам загрузчик решений не понимает смысл текста: оценку выполняет указанный
reviewer. В сохранённых A/B решениях это Codex в текущей сессии, после просмотра
всех 20 ответов и карточек. Это не независимая человеческая разметка.

## Метрики

- Recall@k — среднее по случаям с эталонными источниками. Части сопоставляются
  с исходным `film.source_id`; повторные части не удваивают источник.
  Для точного маршрута учитываются извлечённые карточки.
- Recall@1 сохранён как дополнительная диагностика ранжирования.
- Строгие фильтры проверяются по всем retrieved hits и карточкам, указанным
  в рекомендациях или цитатах ответа. В знаменателе только случаи с фильтрами.
  Пустая выдача проходит эту проверку, но сама по себе не доказывает качество.
- Приёмка требует ожидаемого статуса, автоматической проверки ограничений
  и всех четырёх смысловых флагов. Пока разметка неполна, итоговая доля `null`.
- Технические ошибки и невыполненные случаи не исчезают из знаменателя
  полного набора: они дают ноль в Recall и не считаются принятыми ответами.
  Их количества также показываются отдельно.
