# Ответ с проверяемыми цитатами

Экспериментальный режим extractive разделяет выбор подтверждений и формирование
текста. Модель возвращает только status и существующие movie_id/fragment_ids.
Код копирует цитаты из переданного контекста, добавляет название, год и
длительность из карточки. Публичный формат Answer не менялся.

## Запуск

Используются существующие `.venv`, `.env` и опубликованный индекс. Для
расширенного набора нужен alias cartoons-expanded и соответствующий каталог.
`ask` принимает `--generator-mode extractive`. Реальный эксперимент выполнен:

```bash
HF_HUB_OFFLINE=1 QDRANT_ALIAS=cartoons-expanded PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli evaluate run --catalog data/catalog-expanded.json --questions data/questions-expanded-retry.jsonl --output artifacts/expanded-extractive-2026-10-26 --label extractive-four-case --k 3 --retrieval-k 10 --context-movies 3 --delay-seconds 10 --generator-mode extractive --prompt-version extractive-ru-v1
```

Существующий output не перезаписывается. Для нового повторения выберите новый
каталог. Допустим только prompt extractive-ru-v1 либо отсутствие явного prompt.
Несовместимое сочетание отклоняется. По умолчанию остаётся grounded/v2.

## Контракт

Пример ответа модели, который ещё не является публичным Answer:

```json
{
  "status": "answered",
  "selections": [
    {"movie_id": "film-01", "fragment_ids": ["film-01#plot"]}
  ]
}
```

Каждый ID связан с целым переданным chunk; при отсутствии chunks доступен
полный synopsis карточки. Короткие описания сохраняются целиком. Модель не
может задать диапазон символов, удалить отрицание изнутри фрагмента или
прислать свободный reason. Неизвестные/чужие ID, повторы, пустой выбор
при answered, дополнительные поля и искажённые фрагменты дают GroundingError.
Технический отказ не превращается в insufficient.

Принадлежность текста карточке проверяется с нормализацией пробелов,
совместимой с SentenceChunker; выводится исходный chunk.text без переписывания.
Цитаты заключены в кавычки. Источники связывают выбранные карточки и части;
исходный source_id карточки также поддерживает её метаданные.

Для count, lookup и compare_duration модель не вызывается. При подсчёте
и сравнении код сверяет ExactResult, число/знак разницы, единицы и источники
с контекстом и формирует ответ по шаблону. LOOKUP в renderer v2 возвращает
метаданные и полный дословный synopsis: этот intent означает выбор карточки,
а не обязательно вопрос о годе или длительности. Так отвечаются и сюжетные
вопросы с названием фильма. Даже ответ о длительности включает сюжет —
это выбранная простая стратегия для общего LOOKUP без нового парсера.
Нулевой count — answered с пустыми источниками. При этом
сборка RAG всё ещё использует обычные настройки и проверяет опубликованный
снимок; для полностью локальных точных запросов остаётся команда exact.

## Архитектура и ограничения

extractive.py не зависит от провайдера: проверяет выбор и собирает Answer.
adapters/gemini_extractive.py содержит схему выбора и использует прежний
GeminiHTTP. Декодер complete structured-кандидата общий с обычным генератором;
повторы и смена модели не добавлены. Bootstrap выбирает реализацию через
AnswerGenerator, а CLI передаёт mode. Manifest фиксирует generator_mode,
prompt_version и renderer_version. Для внедрённого объекта mode=custom:
renderer не угадывается, требуется явный GeneratorIdentity; отдельные
настройки mode/prompt при подмене запрещены.

Проверка происхождения не доказывает релевантность фильма, полноту цитат или
отсутствие противоречий между ними. Поэтому смысловая приёмка остаётся
отдельной. Для длинных карточек доступны только переданные части.
Полные цитаты длиннее пересказа; max_output_tokens ограничивает выбор ID
моделью, а не скопированный приложением текст.

## Проверки

12 новых тестов: цитаты и числа, части и отрицания, выдуманные/чужие ID,
свободный текст, подмена chunk, count/zero-count, сравнения, lookup без LLM,
ошибочные вычисления, технические ошибки, статусы и метаданные композиции.
Затем добавлен сквозной тест сюжетных LOOKUP через SearchService на трёх
вопросах. Всего 145 прошли, 3 интеграционных пропущены. Прежние проверки
grounded сохранены, новых зависимостей нет.
[Исправление LOOKUP](../artifacts/extractive-lookup-fix-2026-10-26/README.md).

[Реальный четырёхвопросный прогон](../artifacts/expanded-extractive-2026-10-26/README.md):
два принятых ответа и два HTTP 503. Из трёх запросов выбора успешен один;
подсчёт выполнен кодом без Gemini. Общая приёмка 2/4 (50%), а не 100%.
Общее улучшение качества не заявляется, исторические прогоны сохранены.

Затем выполнен [полный прогон всех 20 вопросов](../artifacts/expanded-extractive-full-2026-10-26/README.md)
с renderer v2: 9 принятых ответов без LLM и 11 HTTP 503, общий результат
9/20 (45%). Все 20 подготовок сохранены, Recall@1/@3 и фильтры 100%.
Успешных выборов цитат моделью в этом полном прогоне нет, поэтому его
результат не подтверждает смысловое преимущество режима. По умолчанию
остаётся grounded/v2; перед дальнейшими генеративными экспериментами
следует разобраться с доступностью настроенного API.
