# Фильтрация по году выпуска

Год стал точным ограничением `Filters.year_gte/year_lte`, обе границы
включительны. Он применяется вместе с длительностью и movie_ids: в Qdrant
до ранжирования/top-k, в JsonExactCatalog по полному активному каталогу.
Поле year уже сохранялось в payload; новые снимки дополнительно создают
целочисленный payload-index для year. Для корректности фильтра существующий
снимок переиндексировать не требуется; основной индекс не перепубликовывался.

| Формулировка | Условие |
| --- | --- |
| С / начиная с / не ранее / не раньше 1990 года | year_gte=1990 |
| Не позже / не позднее 1990 года | year_lte=1990 |
| После / позже / позднее 1990 года | year_gte=1991 |
| До / раньше / ранее 1990 года | year_lte=1989 |
| В 1990 году / 1990 года | year_gte=year_lte=1990 |
| С 1980 по 1990 год | year_gte=1980, year_lte=1990 |

Годы — целые 1–9999; пересечение диапазонов не должно быть пустым.
Правила принимают четырёхзначные годы. Оператор разбирается вместе с годом;
нераспознанные маркеры отношения перед точным годом и незавершённые условия
требуют уточнения. Например, «от 1990 года» и «новее 1990 года» не должны
становиться равенством 1990. Без слова «год» верхняя/нижняя граница
допускается в конце фразы или перед пунктуацией/«и»/«или». Другие единицы,
дробные годы, отрицания условия, неоднозначное «между» и альтернативы «или»
требуют уточнения. Это ограниченная грамматика, не универсальный разбор дат.

`ru-rules-v1.2.1` выделяет годовые условия до разбора минут и удаляет их из
семантического запроса. Точный count поддерживает год и длительность без
сюжетного условия, lookup сохраняет запрошенный год названной карточки.
LLM-режим использует тот же Filters: adapter/prompt `gemini-plan-ru-v3`, decoder
`planner-decoder-v4`. Новые поля обязательны в JSON-кандидате модели, при
отсутствии ограничения они null. Типы и пересечение проверяются кодом.
Устаревший early_reason=unsupported_year_filter удалён; остальные ранние
объяснения по-прежнему формируются кодом (`early-replies-ru-v2`).

## Команды

Офлайн, без .env и провайдеров:

```bash
PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli plan \
  'Посоветуй фильм про море, выпущенный не раньше 1990 года.'

PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli exact \
  'Сколько фильмов с 1980 по 1990 год и короче 90 минут?' \
  --catalog data/catalog-expanded.json
```

Первая команда даёт search и year_gte=1990. Вторая возвращает 7 фильмов.
Их список и исходные метаданные проверены отдельно: film-23, film-25,
film-27, film-28, film-29, film-30, film-32.

Поиск с существующим E5/Qdrant, без Gemini:

```bash
PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli search 'море' \
  --year-gte 1980 --year-lte 1990 --duration-lt 90
```

Эта команда использует alias из настроек. Для фильмов 1980-х выберите отдельно
опубликованный cartoons-expanded и соответствующий каталог в RAG-командах;
исходный каталог содержит только фильмы 2018–2025 годов, поэтому поиск по
1980–1990 в основном индексе пуст. CLI search принимает явные флаги и не
вызывает планировщик. `ask` с тем же вопросом сначала строит план и применяет
годовой фильтр; генерация обычного ответа по-прежнему требует Gemini.
`--planner-mode gemini` выбирает модель для разбора вопроса дополнительно.

## Версии артефактов и старые оценки

Новые evaluate run пишут artifact_schema_version=3 с year_gte/year_lte в
фильтрах плана и эталонного случая. Хеши новых случаев/трасс включают эти поля.
`fingerprint()` не менялся: он по-прежнему хеширует точный канонический JSON.

Чтение схем 1/2 явно восстанавливает прежнее представление Filters только
с отсутствующими/null годовыми границами. Ненулевое годовое условие в старой
схеме отклоняется, а не теряется. Привязки case/trace/prepared/reviews и старые
метрики сохранены; старые архивы не переписываются. Новая метрика строгих
фильтров включает случаи с одним лишь ограничением года.

Для новых прогонов исходных 10 вопросов используется
[data/stage-expectations-v2.json](../data/stage-expectations-v2.json)
(`baseline-stages-v2-year-fields`). Версия v1 остаётся для архивов схем 1/2.
Отчёт по этапам имеет версию stage-quality-v2. Старый year-filter из опыта
планировщика был размечен как clarify при прежних возможностях: его ожидания
и оценки сохраняются как история; повтор текущих правил на нём покажет
намеренно изменившееся поведение.

## Проверено

На предыдущем этапе 189 тестов прошли с реальными Qdrant/E5; после
операторной правки ru-rules-v1.2.1 выполнен новый полный прогон:
**190 прошли без пропусков**. Основной и расширенный индексы сохранились.
DB-тест включает границу 1990, год/длительность перед top-k и отсутствие
payload-index year.

Gemini-планировщик проверен двумя отдельными прогонами одних 13 случаев.
В первом получено 12 планов и один технический сбой. В повторе получены все
13 без технических ошибок, но count с нижней границей 1990 добавил ненужный
year_lte=9999: локальный результат 20 правильный для текущих карточек,
строгое соответствие эталону — 12/13. Подсчёт за 1980–1990 при <90 минутах
и все четыре ранние причины прошли. Попытки не объединяются. Обычные
рекомендации не генерировались и их качество не проверялось.
