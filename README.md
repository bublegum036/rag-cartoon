# Поиск мультфильмов по описанию

Решение задания из [README.txt](README.txt). Факты берутся только из
`catalog.json`; исходный каталог и 10 вопросов сохранены.

Реализован этап индексации и поиска: локальная embedding-модель
`intfloat/multilingual-e5-small`, Qdrant через REST, публикация снимка индекса,
строгие фильтры и команды `index`/`search`. Добавлен отдельный планировщик
на правилах и команда `plan`. Точные операции над JSON-каталогом доступны
командой `exact`. Команда `ask` объединяет планировщик, проверенный снимок
Qdrant/JSON, точные операции и Gemini. Добавлен `evaluate`; все 10 вопросов
выполнены для A и B. Приёмка по rubric выросла с 9/10 до 10/10 после одной
правки prompt. [Разбор и метрики](docs/ab-report.md).
`search` использует явные фильтры и возвращает фрагменты/карточки;
`ask` разбирает вопрос ограниченной грамматикой `ru-rules-v1.1`.

Для следующего эксперимента создан [расширенный каталог из 40 фильмов](data/README.md):
12 исходных и 28 новых вымышленных карточек 1970–2000 годов. Он загружается
отдельно через `--catalog data/catalog-expanded.json`. Для него подготовлены
20 вопросов и опубликован alias `cartoons-expanded`. E5/Qdrant-проверка дала
Recall@1 и @3 = 100% по 11 семантическим случаям с эталоном. Первый прогон
Gemini дал 16 принятых Codex ответов из 20 и 4 технические ошибки; общая
приёмка — 80%. [Ответы и ограничения метрик](artifacts/expanded-run-v2-2026-10-26/README.md).
Основной индекс сохранён.

Новые `evaluate run` сохраняют найденные фрагменты, контекст и вычисления
до генерации. При сбое Gemini эти данные остаются доступными для проверки
поиска; ошибка продолжает учитываться в доле приёмки ответов.
[Проверка сохранения контекста](artifacts/pre-generation-evidence-2026-10-26/README.md).

В [отдельном повторе четырёх технических ошибок](artifacts/expanded-retry-v2-2026-10-26/README.md)
получены четыре ответа без сбоев, принято 3/4: в истории механического кита
пропущена обязательная деталь rubric. Исходный результат 16/20 сохранён.
[Артефакты расширения](artifacts/expanded-retrieval-2026-10-26/README.md).
Исходные A/B-результаты относятся к 12 карточкам.

## Окружение и запуск

Python 3.11+ и Docker Compose. Пакеты Python устанавливаются в `.venv`,
параметры приложения хранятся в `.env`. Эти файлы и кэш модели исключены из Git;
в репозитории есть шаблон `.env.example`.
Проверенная установка для CPython 3.13 на macOS arm64 использует lock:

```bash
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install --require-hashes --only-binary=:all: -r requirements/search-macos-arm64-py313.lock
python -m pip install --no-deps --no-build-isolation -e ".[search]"
python -m pip check
```

Lock включает зависимости поиска и backend сборки. Порядок обновления:
[requirements/README.md](requirements/README.md).
Для других платформ и версий Python отдельный lock пока не проверен.
Обычная установка `python -m pip install -e ".[search]"` доступна, но заново
разрешает версии зависимостей и не воспроизводит зафиксированное окружение.

Если `.env` ещё отсутствует, скопируйте `.env.example` в `.env`.
Затем из корня проекта:

```bash
docker compose up -d qdrant
PYTHONPATH=src python -m cartoon_rag.cli validate-data
PYTHONPATH=src python -m cartoon_rag.cli index
PYTHONPATH=src python -m cartoon_rag.cli search "море и дружба" --duration-lt 90
PYTHONPATH=src python -m cartoon_rag.cli search "девочка и кит чинят маяк" --limit 3
```

После установки пакета доступно и сокращение `cartoon-rag`.
Первое обращение к embedding-модели скачивает ONNX-веса с Hugging Face.
Модель работает на CPU, ключ API для неё не нужен. Точная ревизия весов
закреплена в настройках; менять её нужно вместе с переиндексацией.

`--duration-lt 90` означает строго `< 90`; `--duration-lte 90` означает `<= 90`.
`--movie-id film-01` ограничивает поиск фильмом; флаг можно повторять.
`--limit` задаёт число фрагментов. В JSON `retrieved` содержит отдельные части,
метаданные и оценки, а `movies` — фильмы без повторов: каждый элемент содержит
`film`, выбранные `chunks` и лучший `score`. Это результат поиска,
готовый ответ модели здесь ещё не генерируется.

`index` возвращает типизированный результат публикации в JSON: `index_name`,
`snapshot_id`, идентификатор модели, fingerprint каталога/частей и их количество.
Векторы передаются в хранилище вместе с идентификатором создавшей их модели;
несовпадение с моделью поиска отклоняется до записи. После перехода со старого
формата идентификатора (`fastembed_version`) на `implementation_version`
необходимо повторить `index`.

`.env` читается как набор буквальных `KEY=value`; поддерживаются кавычки и
отдельные строки комментариев. Подстановка переменных и shell-команды не
выполняются. Переменные окружения процесса имеют приоритет. Другой файл
настроек можно выбрать через `--env-file <path>` **перед** именем команды.
Для тестового каталога используйте `index --catalog <path>` и отдельный
`QDRANT_ALIAS`, чтобы не менять основной индекс.

Qdrant доступен по `http://127.0.0.1:6333` и хранит данные в Docker volume.
Остановить сервис без удаления данных: `docker compose down`.

## Разбор вопроса без поиска

`plan` возвращает `QueryPlan` и работает без Qdrant, E5 и чтения `.env`:

```bash
PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli plan "Хочу мультфильм про море и дружбу, короче 90 минут."
PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli plan "Подойдёт ли «Коралловая почта», если у меня только 90 минут?"
PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli plan "Сколько мультфильмов короче 90 минут?"
```

Реализация `ru-rules-v1.1` получает только ID и названия активных карточек.
Для другого каталога есть `plan --catalog <path> <question>`.

| Вопрос | План |
| --- | --- |
| Про море, короче 90 минут | `search`, фильтр `< 90` |
| Про море, не больше 90 минут | `search`, фильтр `<= 90` |
| Сколько минут длится «Маяк для кита»? | `lookup`, `movie_ids=["film-01"]` |
| Подойдёт ли «Коралловая почта», если у меня 90 минут? | `compare_duration`, бюджет 90, без фильтра длительности |
| Сколько фильмов короче 90 минут? | `count` по точным условиям |
| Кто озвучивает девочку? | Ранний `insufficient`: в схеме нет актёров озвучивания |
| Сколько он длится? | Ранний `clarify`: нет выбранного фильма |

Это ограниченная русскоязычная грамматика, а не универсальный языковой парсер.
Поддерживаются положительные целые минуты: «короче», «меньше [чем]», «менее»
означают `<`; «не больше», «не более», «не дольше», «не длиннее», «максимум» —
`<=`. Бюджет «у меня N минут» для открытого поиска даёт `<= N`, для названного
фильма — маршрут сравнения. «Успею … за N минут?» также задаёт сравнение.
Названия сопоставляются целиком без учёта регистра, ё/е и разделителей;
склонения и опечатки не исправляются. Неизвестное название в поддерживаемых
кавычках и несколько распознанных названий требуют уточнения. Нераспознанный
текст без кавычек может остаться смысловым запросом. «До 90», дробные числа,
другие единицы времени, нижняя граница, числовой
фильтр года и альтернативные условия длительности пока требуют уточнения.
Подсчёт по сюжету тоже требует уточнения: считать семантический top-k нельзя.
Единица в вопросе «сколько минут длится…» обозначает запрашиваемый факт,
а не условие длительности. Ранний отказ по возрасту применяется к запросам
возрастного допуска/маркировки; сюжет «про героев разного возраста» идёт в поиск.

`plan` не выполняет подсчёт, сравнение или поиск и не возвращает готовый ответ.
Для `< 40` он сохраняет фильтр; наличие подходящих карточек проверяет следующий
сценарий поиска. `search` по-прежнему использует явные CLI-флаги и не вызывает планировщик.

## Точные операции над каталогом

`exact` строит план и выполняет `lookup`, `count` или `compare_duration`
без Qdrant, E5, чтения `.env` и генерации текста:

```bash
PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli exact "Сколько минут длится „Маяк для кита“?"
PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli exact "Сколько фильмов в каталоге?"
PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli exact "Сколько мультфильмов короче 90 минут?"
PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli exact "Сколько фильмов короче 40 минут?"
PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli exact "Подойдёт ли «Коралловая почта», если у меня только 90 минут?"
```

JSON содержит `plan`, `context` с полными карточками и `exact_result`.
В контексте `chunks` пуст: фрагменты embeddings для точного факта не создаются.
`lookup` возвращает карточку с длительностью 78 минут и `exact_result: null`.
Подсчёт возвращает `value`, `unit: "movies"` и ID всех подтверждающих карточек:
всего 12, короче 90 — 9, короче 40 — 0. Нулевой подсчёт имеет пустые
`context`/`source_ids`; это вычисленный ноль, а не отсутствие результата.
Сравнение возвращает `unit: "minutes"` и разницу «длительность − бюджет»:
для «Коралловой почты» это `96 − 90 = 6`; ноль означает точное совпадение,
отрицательное число — запас времени.

Каталог загружается один раз, планировщик и точная операция используют
те же актуальные активные версии. Для другого файла есть `exact --catalog <path>`.
Прежняя версия не восстанавливается после неактивной последней версии.
Точный подсчёт обходит весь подходящий набор, независимо от top-k и лимита
контекста поиска. Ошибка чтения файла завершается ненулевым кодом;
отсутствующая карточка возвращает пустой контекст и `exact_result: null`.
Для раннего `clarify`/`insufficient` сохраняется статус в `plan.early_status`;
семантический вопрос завершается ошибкой маршрута, не подменяется подсчётом.

Это результат точной операции, без полей готового ответа. При будущей сборке
полного RAG потребуется проверить согласованность JSON-снимка с опубликованным
индексом Qdrant; команда `exact` к нему не обращается.

## Ответы через Gemini

Создайте ключ в [Google AI Studio](https://aistudio.google.com/api-keys)
для проекта **Free Tier без подключённого billing** и добавьте в `.env`:

```dotenv
GEMINI_API_KEY=ваш_ключ
GEMINI_MODEL=gemini-3.1-flash-lite
GENERATION_TIMEOUT_SECONDS=30
GENERATION_MAX_OUTPUT_TOKENS=2048
```

На 25 октября 2026 года эта модель поддерживает структурированный JSON
и имеет бесплатный тариф: [модель](https://ai.google.dev/gemini-api/docs/models/gemini-3.1-flash-lite),
[тарифы](https://ai.google.dev/gemini-api/docs/pricing),
[billing](https://ai.google.dev/gemini-api/docs/billing).
Приложение не определяет тариф ключа: бесплатность обеспечивается настройкой
проекта. Лимиты смотрите в [AI Studio](https://ai.google.dev/gemini-api/docs/rate-limits).
Автоматических повторов, переключения модели и платного fallback нет;
429, таймаут и незавершённый ответ дают отдельную техническую ошибку.
Ключ остаётся в локальном `.env`, отправляется только в заголовке Gemini API
и не включается в контекст, ответы или трассы. Python-зависимости не добавлены:
адаптер использует REST и стандартную библиотеку.

После установки и `index`:

```bash
PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli ask "Хочу мультфильм про море и дружбу, короче 90 минут." --trace artifacts/my-question.json
PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli ask "Подойдёт ли «Коралловая почта», если у меня только 90 минут?"
```

В stdout возвращается `status`, `text`, `source_ids`, `recommendations`.
`--trace <path>` отдельно сохраняет план, найденные части, контекст,
вычисление и готовый ответ. Ранние `clarify`/`insufficient` работают без
чтения `.env`, загрузки модели и обращения к API/базе.

Перед остальными ответами сравнивается fingerprint активного JSON-каталога
с metadata опубликованной коллекции. Несовпадение даёт `SnapshotMismatch`;
после изменения каталога повторите `index`. Поиск закрепляется за конкретной
физической коллекцией: смена alias не подменяет снимок в уже созданном сервисе.

Gemini получает только вопрос, план, выбранные карточки и готовые точные
вычисления. Структура JSON и ссылки проверяются в коде; смысловую
подтверждённость текста ещё необходимо оценивать по rubric.

## Оценка и A/B

Новый прогон сохраняется в отдельную папку, существующая не перезаписывается:

```bash
PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli evaluate run --label A --output artifacts/replay-A --prompt-version grounded-ru-v1 --k 3 --retrieval-k 10 --context-movies 3 --delay-seconds 10
PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli evaluate run --label B --output artifacts/replay-B --prompt-version grounded-ru-v2 --k 3 --retrieval-k 10 --context-movies 3 --delay-seconds 10
```

Теперь в `ask` по умолчанию используется prompt v2; v1 сохранён для повторения.

Для `evaluate run` доступен экспериментальный `--prompt-version grounded-ru-v3`.
На четырёх выбранных случаях [сравнение с v2](artifacts/expanded-retry-v3-2026-10-26/README.md)
не улучшило приёмку: 3/4 → 3/4, один сюжетный пропуск исправлен, один числовой
факт потерян. v2 остаётся версией по умолчанию.
`evaluate run` записывает вопросы, найденные ID/части, контексты, ответы,
трассы, ошибки и manifest с параметрами модели и физической коллекцией.
При Gemini 401/403/429 дальнейшие запросы прекращаются, невыполненные случаи
остаются в отчёте. Настройки с ключами не сериализуются.

Смысловая приёмка выполняется отдельно по rubric, фактам, ограничениям
и источникам. До её завершения `answer_acceptance_rate` равен `null`.
Для сохранённых прогонов решения уже заполнены после просмотра Codex:

```bash
PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli evaluate score --run-dir artifacts/ab-A-2026-10-25 --reviews artifacts/ab-A-2026-10-25/reviews.json
PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli evaluate score --run-dir artifacts/ab-B-2026-10-25 --reviews artifacts/ab-B-2026-10-25/reviews.json
```

`score` работает офлайн и проверяет привязку решений к хешам случая и trace.
Новые ответы требуют новой проверки; автоматически копировать старую разметку
на повторный прогон нельзя. [Формат решений и определения метрик](docs/evaluation.md).

| Метрика | A | B |
| --- | --- | --- |
| Recall@3, 7 случаев с источниками | 100% | 100% |
| Recall@1, те же случаи | 85,7% | 85,7% |
| Принято по rubric и фактам | 9/10 | 10/10 |
| Строгие фильтры, 2 случая | 100% | 100% |

В A ответ про щенка пропустил роль радиопередачи, хотя она была в контексте.
В B изменён только prompt: требуется конкретный способ решения сюжетной
проблемы. Модель, индекс, планы, найденные ID и контексты остались теми же.
Это один проход на маленьком наборе, с приёмкой Codex, а не независимая
человеческая оценка. [Полный отчёт и артефакты](docs/ab-report.md).

## Проверки

Локальные проверки не требуют скачивания модели и запуска базы:

```bash
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli validate-data
git diff --check
```

Проверки реального Qdrant и модели включаются отдельно. Они используют
случайный тестовый alias и удаляют только свои коллекции; основной каталог
не меняется. Сначала запустите Qdrant и установите зависимости.

```bash
QDRANT_INTEGRATION_URL=http://127.0.0.1:6333 RUN_SEMANTIC_SMOKE=1 \
  PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -p test_qdrant_live.py -v
```

Без `RUN_SEMANTIC_SMOKE=1` выполняются только проверки базы с заранее
заданными векторами. Они проверяют фильтрацию до top-k, границы `<`/`<=`,
повторную индексацию, обновление film-01 с 78 до 92, сбой загрузки и пустой снимок.
С флагом дополнительно проверяется поиск кита, робота и морского сюжета с E5.

| `src/cartoon_rag/adapters/gemini.py` | Gemini REST, JSON-схема, prompt и декодирование ответа |

| `src/cartoon_rag/settings.py` | `.env` и проверка настроек |
| `src/cartoon_rag/bootstrap.py` | Сборка конкретных провайдеров |
| `src/cartoon_rag/application.py` | Сценарий будущего полного RAG |
| `src/cartoon_rag/evaluation.py` | Оценка и трассы |
| `tests/` | Локальные и включаемые интеграционные проверки |
