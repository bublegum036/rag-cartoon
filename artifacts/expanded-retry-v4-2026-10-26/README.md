# Prompt v4: числовые факты и сюжетная цепочка

26 октября 2026 к v3 добавлена общая проверка полноты ответа: сюжет не
должен вытеснять числовые факты вопроса; при ограничении длительности нужно
явно назвать длительность выбранного фильма и её соответствие условию.
Также запрещено выводить мотивы/эмоции только из последовательности событий.
Названий фильмов, ID и эталонных ответов в новой инструкции нет.
[Изменение prompt](prompt-diff.patch).

Сначала проверены те же четыре случая. Переход к полным 20 вопросам был
условным: требовалось пройти первый этап без регрессий. Из-за двух HTTP 503
это условие не подтверждено, полный прогон v4 **не запускался**. v2 остаётся
по умолчанию; v4 доступен как экспериментальный вариант.

## Результат первого этапа

| Показатель | v2 | v3 | v4 |
| --- | --- | --- | --- |
| Сохранённых ответов | 4 | 4 | 2 |
| Технических ошибок | 0 | 0 | 2 |
| Принято по общему знаменателю | 3/4 — 75% | 3/4 — 75% | 2/4 — 50% |
| Recall@1 и @3 по трём случаям с эталоном | 100% | 100% | 100% |
| Проверка фильтра длительности | 1/1 | 1/1 | 1/1 |
| Подготовок | 4 | 4 | 4 |

Это не доказательство ухудшения смыслового качества v4. Два полученных
ответа приняты, но нет ответов на два других вопроса. Главная гипотеза —
сохранение 78 минут в sea-short — осталась непроверенной. Нельзя объявлять
исправление регрессии по одним только правильным metadata.

| Случай | Итог v4 |
| --- | --- |
| sea-short | HTTP 503; подготовка сохранена, готового ответа нет |
| space | Принят: механизм радиопередачи назван явно |
| mechanical-whale | Принят: рычаг/лебёдка и применение данных для прохода лодок |
| count-all | HTTP 503; вычисление 40 и все карточки сохранены, ответа нет |

Было четыре реальных вызова Gemini, два успешны. Автоматических повторов,
смены модели, включения биллинга или подстановки прежних ответов не было.
run завершился с кодом 1, manifest.state=completed_with_errors. Ошибки
остаются в знаменателе. 100% среди двух сохранённых ответов не заменяют
основную долю приёмки 50%.

## Сравнимость и наблюдаемость

Вопросы, rubric и протокол проверки не менялись. Все runtime-поля, кроме
prompt_version, совпали с v2/v3. Подготовки всех четырёх случаев идентичны:
план, фрагменты, контекст и вычисления те же. [comparison.json](comparison.json)
содержит сверку и причину, по которой полный этап не начат.

В отличие от первого полного расширенного прогона формата 1, ошибки
генератора теперь не лишают нас данных поиска. У sea-short сохранена
правильная карточка с 78 минутами и фильтром <90; у count-all сохранены
ExactResult=40 и полный контекст из 40 карточек с 40 источниками.
Поэтому Recall и фильтр подтверждены несмотря на отсутствие двух ответов.
Это диагностика подготовки, не приёмка отсутствующих ответов.

Codex прочитал text и reason двух полученных ответов по прежним rubric,
проверил факты и ссылки. Проверка не независимая и не слепая. Пропуски
генерации не получили выдуманных решений по смыслу; judgment у них no_answer.

  Существующие проверки охватывают запросы всех четырёх prompt-версий,
  стабильность архивных v2/v3 и передачу v4 через CLI.
- Валидация: [12/10](validate-base.json), [40/20](validate-expanded.json),
  [40/4](validate-retry.json).

Исходные данные и все предыдущие архивы сверены с HEAD и не менялись.
Малый отобранный поднабор, вариативность модели и недоступность API
ограничивают вывод. Ни успех v4 на полном наборе, ни устранение HTTP 503
не заявляются. Следующий реальный эксперимент — отдельная проверка после
восстановления доступности провайдера; текущие ошибки нужно сохранить.
