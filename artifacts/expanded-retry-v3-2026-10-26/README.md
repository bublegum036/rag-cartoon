# Эксперимент с причинной цепочкой: prompt v3

26 октября 2026 к prompt v2 добавлена одна общая инструкция: в сюжетном
ответе сохранять действие, результат и его дальнейшее назначение/пользу,
если это явно есть в карточке. Факты конкретных фильмов, ID и ответы
из rubric в инструкцию не включались. [Разница prompt](prompt-diff.patch).

На тех же четырёх случаях проведено сравнение с
[предыдущим v2](../expanded-retry-v2-2026-10-26/README.md). Все runtime-поля,
кроме prompt_version, совпали: модель, лимиты, поиск, snapshot и embeddings.
Вопросы, rubric, протокол оценки и все данные подготовки идентичны.
План, найденные фрагменты, контекст и точные результаты не менялись.
Это сравнение на отобранном поднаборе, не новая полная пара A/B задания.

**Общего улучшения нет.** Исправление одного пропуска сопровождается новой
регрессией. v3 сохранён для воспроизводимости как экспериментальный вариант,
по умолчанию остаётся grounded-ru-v2. Расширенная проверка всех 20 случаев
с v3 не запускалась; на основании этих четырёх ответов переход не обоснован.

## Наблюдаемые изменения ответа

В [mechanical-whale](mechanical-whale/answer.json) явно сказано, что данные
измерений помогают рыбакам выбрать безопасный проход для лодок. Рычаг,
лебёдка и механическая природа кита также сохранены. Rubric теперь выполнен.

В [sea-short](sea-short/answer.json) развёрнут сюжет спасения и ремонта маяка,
но ни text, ни reason не содержат требуемых rubric 78 минут. В metadata
и контексте длительность правильная, фильтр <90 соблюдён — это не нарушение
фильтра извлечения, а пропуск обязательного факта в готовом ответе.
Дополнительно text приписывает киту мотив «в благодарность»; карточка сообщает
последовательность спасения и помощи, но прямо не задаёт этот мотив.
Поэтому facts_supported=false наряду с rubric_passed=false. Даже без этого
дополнительного замечания пропуска длительности достаточно для отклонения.

Оценивал Codex в текущей беседе, не независимо и не вслепую. Прочитан весь
JSON, включая reason. Факты из context не засчитывались как автоматически
присутствующие в ответе. Критерии после получения ответов не менялись;
протокол побайтово совпадает с использованным для v2.

- Проверки данных: [12/10](validate-base.json), [40/20](validate-expanded.json),
  [40/4](validate-retry.json).

В этом прогоне было четыре реальных вызова Gemini без автоматических
повторов, смены модели или включения биллинга. Исходные данные, v2, полный
расширенный прогон и старые A/B не переписывались. Push не выполнялся.
Это единичные генерации малого выбранного набора: неизменные параметры
не устраняют вариативность ответа провайдера даже при temperature=0.
Результат не доказывает причинный эффект инструкции за пределами наблюдения.

Следующая гипотеза — явно сохранять числовые факты, относящиеся к ограничениям
вопроса, при расширении сюжета. Её следует проверять отдельной версией и
расширенным набором; в этом этапе дополнительной правки не было.
