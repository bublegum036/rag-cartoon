# Планировщик `ru-rules-v1` — 25 октября 2026

Реализован `QueryPlanner` на правилах и отдельная CLI-команда `plan`.
Планировщик получает только ID и названия активных фильмов, без фактов карточек,
эталонных ответов и rubric. Зависимости Python не менялись.

## Проверки

Из корня проекта:

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
PYTHONPATH=src python3 -m cartoon_rag.cli validate-data

QDRANT_INTEGRATION_URL=http://127.0.0.1:6333 RUN_SEMANTIC_SMOKE=1 \
  PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v

PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli plan "Хочу мультфильм про море и дружбу, короче 90 минут."
PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli plan "Подойдёт ли «Коралловая почта», если у меня только 90 минут?"
PYTHONPATH=src .venv/bin/python -m cartoon_rag.cli plan "Сколько мультфильмов короче 90 минут?"
```

- [tests-local.log](tests-local.log): 60 прошли, 3 интеграционных пропущены.
- [tests-live.log](tests-live.log): все 63 теста прошли, пропусков нет.
- 22 новых теста в `test_planner.py`: границы `<`/`<=`, перефразировки,
  неизвестные/неоднозначные названия, отсутствующие поля, недопустимые условия,
  COUNT, сравнение с бюджетом и передача плана в прикладной сервис.
- В существующий семантический тест добавлен план из естественного языка:
  реальная E5/Qdrant-выдача включает film-01, все hits короче 90 минут.
- `validate-data`: 12 активных карточек, 10 вопросов.
- [cli-search.json](cli-search.json), [cli-compare.json](cli-compare.json),
  [cli-count.json](cli-count.json), [cli-clarify.json](cli-clarify.json):
  фактический вывод новой команды, включая выбор каталога через `--catalog`.
- [plans.json](plans.json): планы всех 10 исходных вопросов. В обработчик
  передавался только `question`; ID используется лишь для подписи записи.

Проверено на Python 3.13.15, macOS arm64, с уже работающим Qdrant 1.17.0
и E5 из существующего кэша. Тесты используют случайные alias и не публикуют
данные в основной индекс. Для базы и загрузки метаданных модели использован
доступ за пределами песочницы. Каталог и вопросы не изменены.

## Граница результата

Семь исходных случаев направляются в `search`, один — в `compare_duration`,
один даёт ранний `insufficient`, один — `clarify`. Для `no-match` план содержит
`< 40`, но не ранний отказ: планировщик не знает длительности карточек.
Сравнение содержит бюджет 90 и ID film-02, без фильтра, который удалил бы
нужную карточку. Подсчёт по сюжету требует уточнения, а не подсчёта top-k.

Это проверка планирования, не полный RAG-прогон. В `plans.json` нет найденных
фрагментов, контекста и финальных ответов. Recall@k, answer acceptance rate
и A/B здесь не вычислялись. Точные операции и генератор — следующий этап.
Поддерживаемая грамматика и её ограничения перечислены в основном README.
