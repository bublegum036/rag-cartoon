# Диагностика HTTP 503 Gemini — 26 октября 2026

После полного extractive-прогона выполнена ограниченная диагностика той же
модели gemini-3.1-flash-lite и той же настройки ключа. Код приложения,
каталог, вопросы, индексы и прошлые прогоны не менялись. Базовый коммит f0cadcb.

## Наблюдения

| Проверка | Результат |
| --- | --- |
| GET /v1beta/models/gemini-3.1-flash-lite | HTTP 200 |
| Версия, возвращённая API | 3.1-flash-lite-05-2026 |
| Поддерживаемые методы | в том числе generateContent |
| Минимальная генерация без RAG и JSON-схемы | HTTP 503, UNAVAILABLE |
| Сообщение Google | высокая нагрузка на текущую модель, предложено попробовать позже |
| Retry-After | не предоставлен |
| Вызовов генерации | 1 |
| Проверка JSON-схемы | пропущена после отказа минимальной генерации |

Запрос содержал только «Верни только слово OK.» и обычные generationConfig:
temperature=0, candidateCount=1, maxOutputTokens=2048. System instruction,
каталог, цитаты, Qdrant и responseFormat отсутствовали.

Ответ API: `503 / UNAVAILABLE`, сообщение:

> This model is currently experiencing high demand. Spikes in demand are usually temporary. Please try again later.

Это воспроизводит отказ вне RAG и без структурированной схемы. На текущем
запросе провайдер прямо сообщает о высокой нагрузке модели. Нет оснований
править prompt или каталог для устранения этого конкретного 503.

GET 200 подтверждает, что модель зарегистрирована и метод generateContent
объявлен. Это не гарантия успешной генерации. В двух диагностических
запросах не было 400/401/403/429; проверка всех квот/прав проекта не проводилась.
Глобальный инцидент Google не подтверждён: текстовое чтение публичной
статус-страницы не предоставило сведений о её состоянии.

Старые error.json сохраняют только HTTP-код и общую ошибку приложения.
Текущее сообщение не дописывалось в них задним числом: оно относится
именно к этой диагностике. Общая причина прежних отказов согласуется
с наблюдением, но их внутренние сообщения восстановить по старым файлам нельзя.

## Сверка с первичными источниками

Проверено 26 октября 2026:

- [Ошибки GenerateContent](https://ai.google.dev/gemini-api/docs/generate-content/api-errors):
  503 относится к недоступности/перегрузке, тогда как 429 обозначает ограничения
  частоты/квот. Ответ ошибки содержит code, status и message.
- [Structured outputs](https://ai.google.dev/gemini-api/docs/generate-content/structured-output?hl=en):
  используемое responseFormat.text.schema документировано для REST,
  Gemini 3.1 Flash-Lite перечислена среди поддерживаемых моделей.
- [Карточка модели](https://ai.google.dev/gemini-api/docs/models/gemini-3.1-flash-lite.md):
  стабильный ID и поддержка structured outputs совпадают с настройками.

Точная JSON-схема приложения в этой диагностике повторно не отправлялась:
минимальный неструктурированный запрос уже получил 503. Совместимость
схемы сверена по документации, но это не успешная новая проверка structured output.
Ссылки и ограничения чтения статуса записаны в [sources.json](sources.json).

## Артефакты и безопасность

- [diagnostics.json](diagnostics.json): только выбранные поля ответов,
  время и длительность запросов, минимальное тело без ключа.
- [diagnose.py](diagnose.py): одноразовый скрипт, максимум GET и два разных
  POST; второй POST возможен только после успешного первого. В этой попытке
  сделаны GET и один POST. Автоповторов и смены модели нет.
- [verification.json](verification.json): проверки выводов, хеш скрипта,
  неизменность кода/данных/истории.
- [command.txt](command.txt): реально выполненная команда.
- [tests-local.log](tests-local.log): 145 прошли, 3 интеграционных пропущены.
- [validate-base.json](validate-base.json): 12 карточек, 10 случаев;
  [validate-expanded.json](validate-expanded.json): 40 карточек, 20 случаев.

Скрипт не сохраняет ключ, заголовки авторизации или необработанные тела ошибок.
Строки редактируются перед записью, проверена маскировка самого ключа
и URL-кодированной формы. Заголовок x-goog-api-key используется только в памяти.
Не менялись `.env`, модель, биллинг или политика повторов приложения.

Команда отказывается перезаписывать существующий diagnostics.json. Для
будущей ручной проверки нужен новый каталог со скриптом; не удаляйте текущий
отчёт ради повторения. Массовые прогоны сейчас не возобновлялись. Практический
следующий шаг — дождаться доступности настроенной модели и начать с такой
же короткой проверки. Время восстановления из ответа определить нельзя.
